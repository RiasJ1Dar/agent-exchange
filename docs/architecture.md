# Архітектура

Чотири крейти в одному workspace. Залежності йдуть в один бік:
`ui` і `mcp` спираються на `render` і `store`, `store` не знає ні про кого.

| Крейт | Відповідальність | Рядків |
|---|---|---|
| `store` | SQLite: повідомлення, замки, міграції. | ~2000 |
| `render` | Складання `NOW.md` і `agent_talk.md`. | ~2900 |
| `mcp` | Протокол, кадрування, сім інструментів. | ~2800 |
| `ui` | HTTP-переглядач, база **тільки на читання**. | ~2400 |

## Схема бази

```sql
CREATE TABLE messages (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    ts_unix    INTEGER NOT NULL,
    v          INTEGER NOT NULL,
    from_agent TEXT NOT NULL,
    to_agent   TEXT NOT NULL,
    topic      TEXT NOT NULL,
    op         TEXT NOT NULL,
    body       TEXT NOT NULL,
    read_at    INTEGER
);

CREATE TABLE locks (
    topic    TEXT PRIMARY KEY,
    holder   TEXT NOT NULL,
    taken_at INTEGER NOT NULL,
    ttl_sec  INTEGER NOT NULL,
    note     TEXT NOT NULL
);

CREATE INDEX idx_messages_inbox ON messages (to_agent, read_at, id);
```

Прочитаність — це `read_at`, а не булеве поле: видно не лише *чи* прочитано,
а й *коли*. Прочитані з `ts_unix` старшим за 14 діб прибирає внутрішній gc
на `post`/`ack` (не частіше ніж раз на годину на одному з'єднанні).
Непрочитані не чіпає. Окремого MCP-інструмента немає.

## Міграції

Версія схеми живе в `PRAGMA user_version`. Приведення до потрібної версії
йде однією транзакцією `BEGIN IMMEDIATE … COMMIT`, і версія перечитується
**повторно вже під write-lock** — інакше два процеси, що стартують разом,
обидва вирішили б мігрувати.

База, новіша за збірку, не відкривається взагалі: краще відмова, ніж запис
у схему, якої ця збірка не розуміє.

## Кадрування MCP

Транспорт — stdio, JSON-RPC 2.0. Підтримуються **обидва** кадрування:

- по одному JSON на рядок (основне);
- `Content-Length` у стилі LSP.

Тип визначається за першим байтом: `{` — рядкове кадрування, інакше
заголовки. UTF-8 BOM перед першим повідомленням теж переживається.

Стеля кадру — 1 МіБ. Довший не читається в памʼять цілком: хвіст
відкидається, клієнт дістає `-32700`, потік лишається живим.

## Чому без async

Навантаження — десятки повідомлень на добу від двох агентів. Асинхронне
середовище тут додало б залежностей і способів помилитися, не додавши
нічого корисного. `ui` обслуговує зʼєднання послідовно і цього вистачає.
